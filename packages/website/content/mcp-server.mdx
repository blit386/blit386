title: MCP Server

The BLIT386 docs site exposes a [Model Context Protocol](https://modelcontextprotocol.io) server at `/mcp`. AI coding
assistants that support MCP can use it to search the documentation and retrieve summaries without leaving their chat
interface.

## Endpoint

```
https://blit386.dev/mcp
```

Transport: streamable-HTTP (JSON-RPC 2.0 over POST). No authentication required.

Limits: a POST must send a `Content-Length` header (`411` without one) of at most 64 KiB (`413` above that), and a
`search_docs` query longer than 256 characters is refused with JSON-RPC error `-32602`.

## Tools

| Tool | Description |
| --- | --- |
| `search_docs` | Keyword search across the documentation. Returns matching page titles, absolute URLs, and excerpts. Works best with short keywords such as `keyboard input`, not a full sentence. |
| `get_doc_page` | Returns the full markdown of one page. Takes a URL from `search_docs` or `get_docs_summary`, or a site path such as `/docs/guides/input`. |
| `get_docs_summary` | Returns the `llms.txt` summary of the site - a compact index suitable for LLM context windows, with absolute links. |

Building a game with no project yet? Start at [Build a Game](/docs/build-a-game): a starter project, the kit's agent
instructions, guides, and skills, and complete example programs - every page readable through `get_doc_page`.

## Setup

### Claude Code

For your own account, add the server with the CLI:

```bash
claude mcp add --transport http blit386-docs https://blit386.dev/mcp
```

Or check a project-scoped config into your repository root as `.mcp.json`, so every contributor's agent picks it up -
`type` is required for a remote server, since Claude Code skips an entry that has a `url` but no `type`:

```json
{
  "mcpServers": {
    "blit386-docs": {
      "type": "http",
      "url": "https://blit386.dev/mcp"
    }
  }
}
```

Claude Code asks once per project before it uses a server from `.mcp.json`. To skip that prompt, pre-approve the server
by name in the project's `.claude/settings.json`:

```json
{
  "enabledMcpjsonServers": ["blit386-docs"]
}
```

A game scaffolded with `npm create blit386@latest` with Claude Code picked as an assistant already ships both files, so
its contributors get the server with no prompt and no setup of their own.

### Claude Desktop

`claude_desktop_config.json` only configures local (stdio) servers. To connect a remote server like this one, add it as
a Custom Connector instead: open Settings, go to Connectors, choose "Add custom connector", and paste the endpoint URL
above.

### Cursor

Add to `.cursor/mcp.json` in your project:

```json
{
  "mcpServers": {
    "blit386-docs": {
      "url": "https://blit386.dev/mcp"
    }
  }
}
```

### Antigravity

Add to `.agents/mcp_config.json` in your project. Antigravity reads only `serverUrl` for a remote server - `url` and
`httpUrl` are rejected:

```json
{
  "mcpServers": {
    "blit386-docs": {
      "serverUrl": "https://blit386.dev/mcp"
    }
  }
}
```

### Codex

Add to `.codex/config.toml` in your project (Codex reads it only once you trust the project), or to
`~/.codex/config.toml` for every project:

```toml
[mcp_servers.blit386-docs]
url = "https://blit386.dev/mcp"
```

### GitHub Copilot

The Copilot CLI and VS Code read the same project `.mcp.json` as Claude Code, so the entry above covers both. The cloud
agent reads no project file - add the server in the repository's Copilot settings on github.com instead.

### Gemini CLI

Add to `.gemini/settings.json` in your project (Gemini CLI reads it only once you trust the folder). Use `httpUrl`: for
Gemini CLI, `url` means an SSE server, and this one is streamable HTTP:

```json
{
  "mcpServers": {
    "blit386-docs": {
      "httpUrl": "https://blit386.dev/mcp"
    }
  }
}
```

### OpenCode

Add to `opencode.json` in your project. OpenCode calls the key `mcp`, not `mcpServers`, and marks a remote server with
`type`:

```json
{
  "mcp": {
    "blit386-docs": {
      "type": "remote",
      "url": "https://blit386.dev/mcp",
      "enabled": true
    }
  }
}
```

### Zed

Add to `.zed/settings.json` in your project (Zed ignores project settings until you trust the project), or to your own
Zed settings for every project:

```json
{
  "context_servers": {
    "blit386-docs": {
      "url": "https://blit386.dev/mcp"
    }
  }
}
```

## Testing with curl

```bash
# List available tools
curl -s https://blit386.dev/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

# Search the docs
curl -s https://blit386.dev/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"search_docs","arguments":{"query":"palette animation"}}}'

# Read one page in full
curl -s https://blit386.dev/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"get_doc_page","arguments":{"url":"/docs/guides/input"}}}'

# Fetch the llms.txt summary
curl -s https://blit386.dev/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":4,"method":"tools/call","params":{"name":"get_docs_summary"}}'
```

## Discovery

The server publishes a discovery card at `/.well-known/mcp/server-card.json` for clients that support automatic MCP
server discovery.
